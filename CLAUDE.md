# GP2040-CE-D_C_Theo — Project Guide (for Claude Code)

A fork of **GP2040-CE** (fightstick web configurator firmware) that adds a redesigned
"D_C_Theo" web interface. The UI is embedded in the firmware and served on-device at
`http://192.168.7.1`; users connect the same way as stock GP2040 (hold the config button /
plug in). Upstream: `OpenStickCommunity/GP2040-CE` (configured as the `upstream` git remote).

## Where things are

- **UI app:** `www/` — Vite + React 18 + TypeScript, Zustand, proto→TS via `pbjs`.
- **Our code:** everything under `src/**/dc/` plus `src/Store/useConnectionStore.ts` and
  `src/Store/useDcMode.ts`. Stock GP2040 code is otherwise unmodified.
- **Design specs & plans:** `docs/superpowers/specs/` and `docs/superpowers/plans/`.
- **Smoke tests (human-run on hardware):** `docs/*-smoke-test.md`.
- **Build pipeline:** `npm run build` = `build-proto` → Vite → `makefsdata.js` → firmware
  `lib/httpd/fsdata.c`. `src_gen/enums.ts` is generated by `build-proto` — do not hand-edit;
  ignore its build-time drift.

## Commands (run inside `www/`)

- `npm run dev` — mock Express API (:8080) + Vite (:3000). New UI is at `/` and
  `/dc/*`. `npm run dev-board` targets a real device at 192.168.7.1.
- `npm test` — Vitest + React Testing Library.
- `npm run build` — production build + fsdata.
- `npm run lint:dc` — ESLint (`--max-warnings 0`) scoped to OUR files only.
- `npm run size-check` — enforce the flash bundle-size budget.

## Conventions (keep these)

- **Reuse, don't fork stock code.** Device I/O goes through the `WebApi` **default export**
  (e.g. `WebApi.getPinMappings`); profiles go through the stock `useProfilesStore`
  (`saveProfiles` = `setPinMappings` + `setProfileOptions`) so profiles are shared with the
  stock UI.
- **i18n:** all D_C_Theo UI strings go through the **`DC` namespace**
  (`src/Locales/en/DC.jsx`) — the repo's ESLint enforces `i18next/no-literal-string`.
- **Lint gate is scoped.** Upstream's own `src/` currently fails its lint (235+ errors), so
  CI (`.github/workflows/www-ci.yml`) and `lint:dc` lint only our files. Add new
  `src/**/dc/**` files (and any new `src/Store/*` we own) to the `lint:dc` script.
- **Vitest quirks:** the Vitest config intentionally omits `@vitejs/plugin-react` (Vite 4 /
  Vitest 2 refresh-preamble clash) and uses esbuild's automatic JSX; i18n is initialized in
  `src/test/setup.ts` so components render real strings.
- **Styling:** Tailwind with the **`tw-` prefix** (coexists with stock Bootstrap;
  `preflight` off). New files under `src/**/dc/`.
- **No firmware (C++) changes** so far; on-hardware behavior is verified via the human-run
  smoke-test docs, not automated here.

## Architecture

- **D_C_Theo mode** (`src/Store/useDcMode.ts`, persistent, default ON): the nav badge toggles
  it. ON substitutes our enhanced pages into the stock nav via
  `src/Data/dc/routeSubstitutions.tsx` (`/` and `/pin-mapping` → `ControllerViewPage`) and
  shows the connection banner; OFF is untouched stock (banner hidden, grey toggle only).
  Extend the registry to substitute more stock pages (e.g. `/led-config` later).
- **Controller view** (`src/Pages/dc/ControllerViewPage.tsx`): interactive SVG layout
  (leverless / arcade) showing each button's label + GPIO pin; **press-to-identify** via
  `getHeldPins` long-poll; **remap** (pick a function, click buttons); **profiles** bar
  (select/rename/add/enable/copy) via `useProfilesView` over `useProfilesStore`; System Stats
  panel.

## Git / workflow

- This is a standalone repo (separate from any other project). Normal `commit` / `push` to
  `origin` (the fork) is expected. `main` is the integration branch; feature branches merge
  (fast-forward) into it and are deleted.
- Follow TDD (Vitest) for new logic; keep `lint:dc`, `npm test`, `npm run build`, and
  `npm run size-check` green before merging.
